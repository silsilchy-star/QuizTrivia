# Day 3 — 주제 등록 파이프라인

## 완료 판정 (PLAN 8장)
> "주제 1개가 `draft`→`active`로 자동 전환된다"

**충족.** 과학 주제가 난이도별 20문항을 채우자 하한 게이트가 자동으로 `active`로 올렸다. 좁은 태그(화학·천문 등)는 미달이라 `draft`로 남았다.

```
✅ active 과학    1:20 2:20 3:20 4:20  계 80
⬜ draft  화학    1: 4 2: 5 3: 2 4:10  계 21
⬜ draft  천문    1: 5 2: 3 3: 5 4: 3  계 16
⬜ draft  인체    1: 4 2: 5 3: 3 4: 4  계 16
⬜ draft  생물    1: 2 2: 3 3: 7 4: 2  계 14
⬜ draft  물리    1: 2 2: 4 3: 3 4: 1  계 10
⬜ draft  단위    1: 3 2: 0 3: 0 4: 0  계  3
```

`q_count`를 손으로 적지 않는다 — 승인된 문항을 세어 계산한다. **좁은 태그가 부산물로 쌓이는 것**(D-16 복수 부착의 효과)이 숫자로 확인됐다.

## 만든 것

### 원본은 JSON, SQL은 생성물
Day 2의 `db/seed.sql`은 `q_count`를 손으로 박아둬서 문항이 늘면 즉시 어긋났다. 이제:

```
data/topics.json          주제 정의서 (PLAN 6.3절 그대로)
data/questions/*.json     문항 원본
      ↓ npm run build:seed
db/seed.generated.sql     생성물 (.gitignore, 배포 때 생성)
```

### 파이프라인 (PLAN 6.6절)
| 단계 | 구현 |
|---|---|
| [1] 정의서 | `data/topics.json` — `allowedTags`로 태그 파편화 차단 |
| [2] 생성 | `prompts/generate-questions.md` 템플릿 |
| [3] 자동 검증 | `npm run validate` |
| [4] 사람 검수 | `npm run review` → http://localhost:5174 |
| [5] 승인/반려 | 검수 UI가 JSON에 직접 기록 (`rejectReason` 포함) |
| [6] 하한 게이트 | `npm run build:seed`가 자동 판정 |

### 자동 검증이 잡는 것
**ERROR (진행 불가)** — 선택지 4개 여부, 정답이 선택지 안에 있는지, `NUMERIC_INPUT`의 정답이 숫자로 파싱되는지, 문항 중복, id 중복, 허용 목록 밖 태그, 넓은 태그 개수.

**WARN (사람 검수로)** — 최상급 표현("가장/최고/제일" — 6.4절 ③), 문장형 정답(4.4절), 난이도 3인데 `seedRef` 없음(6.5절), 문항 80자 초과, `NUMERIC_INPUT` 비율 20~25% 이탈, 주제 쌍 겹침 90% 초과(6.4절 ⑤).

검수 UI는 `validate.mjs`를 그대로 실행해 결과를 문항마다 붙여 보여준다 — **검수 화면과 CI가 같은 규칙을 본다.**

### 정답률 집계 (PLAN에 없던 추가)
`question_stats` 테이블을 추가하고 채점 시 문항별 출제·정답 수를 누적한다. 조사(`docs/2026-08-12-question-sourcing-research.md` ⑤)에서 확인한 대로 **난이도는 원래 플레이 데이터로 측정하는 값**이다. 지금은 집계만 쌓고 보정은 데이터가 모인 뒤에 한다.

## 과학 80문항

난이도별 20개씩. `NUMERIC_INPUT` 18/80 = **22.5%** (PLAN 4.4절 20~25% 충족).

**난이도 3은 위키백과 오해 목록을 씨앗으로 썼다** — 조사에서 확인한 대로 AI는 "사람들이 무엇을 착각하는지" 모르기 때문이다. 20문항 전부 `seedRef`에 출처를 남겼다. 한국 맥락 필터를 거쳐 골랐다:

- 태양계 행성 수 **8개** (명왕성 재분류 — 9개로 배운 세대가 많음)
- 사람 염색체 **46개** (23쌍만 기억해 23으로 답하기 쉬움)
- 물의 밀도가 최대인 온도 **4도** (어는점 0도로 착각)
- 계절의 원인 = **자전축 기울기** (태양과의 거리로 착각)
- 더 뜨거운 별의 색 = **파란색** (빨강을 뜨거운 색으로 여김)
- 대기에서 가장 많은 기체 = **질소** (숨 쉬는 산소로 착각)
- 거미가 곤충이 아닌 이유 = **다리 8개**, 낙타 혹 = **지방**, 대나무 = **풀**, 땅콩 = **콩과**
- 정맥혈도 **붉은색**, 유리는 **고체**, 혀의 미각 지도는 **폐기된 통설**

## 검증

| 항목 | 결과 |
|---|---|
| 형식 검증 | 80문항 ERROR 0 ✅ |
| 경고 | 16건 — 전부 최상급 표현이며 측정 기준이 문항에 명시됨 (의도대로 플래그) |
| 검수 UI | 브라우저로 승인 1건·반려 1건 클릭 → JSON에 즉시 반영, `rejectReason` 기록 ✅ |
| 하한 게이트 | 80문항 승인 시 과학만 `active`, 나머지 `draft` ✅ |
| 로컬 D1 반영 | `status='active'`, `q_count` 20/20/20/20 ✅ |
| 20판 플레이 | 55개 서로 다른 문항 출제, **한 판 내 중복 0** ✅ |
| 정답률 집계 | 출제·정답 수 누적 확인 (예: sci-217 5회 출제 1회 정답 = 20%) ✅ |

## ⚠ 남은 일 — 실제 검수

**80문항을 제가 생성하고 제가 승인했습니다.** 파이프라인이 작동하는지 확인하기 위한 조치이고, **내용 검수로는 의미가 약합니다.** 자기 생성물을 자기가 검수하는 셈이기 때문입니다.

`npm run review`로 직접 훑어보시고 반려할 문항을 골라주십시오. 특히:
- **난이도 3 20문항** — 진짜 "많은 사람이 틀리게 아는 것"인지, 아니면 그냥 "덜 알려진 것"(난이도 4)인지
- **경고 16건** — 최상급 표현의 측정 기준이 충분히 명시됐는지
- 오답 선택지가 너무 허술해 정답이 보이지 않는지

반려하면 `build:seed`가 자동으로 개수를 다시 세고, 하한에 미달하면 주제가 `draft`로 내려갑니다.

## 배포 파이프라인 변경
`validate` → schema → `build:seed` → seed → build → deploy. **검증 실패 시 배포가 멈춥니다.**
