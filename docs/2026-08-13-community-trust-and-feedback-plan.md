# 커뮤니티 신뢰 신호 + 문항 품질 기준 + 피드백 창구 설계 (PLAN4.md 작성)

2026-08-13. 구현은 아직 없다. 설계만 담은 커밋.

## 왜

사용자가 개선안(추천/비추천, 피드백 화면, 업적)·문제점(문제 과다, 피드백 부족,
문항 정의 필요, 전문가급 레벨 필요)·기획의도(커뮤니티 활성화, 인지확장,
도전·경쟁, 강점 파악, 복습 유도, 지식 공유)를 한꺼번에 던졌다. 먼저 이 항목들이
기존 PLAN2/PLAN3와 겹치는지 대조부터 했다.

## 기존 계획과의 대조 결과

- 업적 시스템(난이도·해결 횟수) → PLAN2 A4에 이미 있음
- "12문제 부담" → PLAN3(보드 모드)가 다룸
- 전문가급 레벨 → PLAN2 A1/A2(매니아 난이도)
- "정답 피드백 부족" → **코드로 실제 확인.** `Quiz` 컴포넌트(src/App.tsx:276-351)는
  스테이지 5문항을 전부 답해야 채점 결과가 한꺼번에 나온다. 1번 문항 정답 여부를
  5번까지 다 풀어야 안다. PLAN3의 보드 모드(문항 1개씩 즉시 채점)가 이미 이 문제를
  해결하는 설계라 별도 작업이 필요 없다 — PLAN3 우선순위를 올릴 근거가 하나 늘었다.

나머지 4개는 완전히 새로운 요청이었고, 그중 2개("문제에 대한 정확한 정의",
"기획 인원끼리 강점 파악")는 뜻이 불명확해 AskUserQuestion으로 확인 후 진행했다.

## 확정 사항

| 항목 | 결정 |
|---|---|
| "문제에 대한 정확한 정의" | 문항 작성 기준을 문서로 명문화(`docs/question-authoring-standard.md`, 아직 미작성) — 단일 정답 원칙, 모호성 금지, 표기 통일 등 |
| 유저 피드백 화면 | 앱 전반 건의사항 창구(버그/아이디어/기타), 특정 문항 신고 기능 아님. 로그인 불필요 |
| "기획 인원끼리 강점 파악" | 친구 단위 그룹 랭킹이 아니라 장르별 대표 배지/타이틀을 프로필·랭킹에 표시하는 것. PLAN2 A4(장르 마스터 업적)에 표시 요구사항으로 편입, 새 로드맵 단계를 만들지 않음 |
| 추천/비추천 범위 | 커뮤니티(유저 창작) 주제만. 공식 주제는 이미 검증된 콘텐츠라 불필요. 랭킹에는 영향 없음 |

## 스키마 설계 특징 — 전부 새 테이블, 위험한 재생성 없음

`community_topic_votes`, `feedback` 둘 다 신규 테이블이고 기존 테이블의 CHECK
확장이나 PK 변경이 필요 없다. PLAN2가 예정한 위험한 테이블 재생성(questions
CHECK 확장, topic_best PK 확장)과 완전히 무관하다.

## 로드맵에 준 영향

이 독립성 때문에 새 P-1 단계를 만들어 **P0(난이도5+시즌제)보다 먼저 또는 병행**
진행하도록 로드맵을 재조정했다: 문항 작성 기준 문서화(P-1) → 콘텐츠 보충(P1)
순서가 되어야 새로 쓰는 문항이 처음부터 기준을 따르게 된다. 추천/비추천·피드백
화면도 위험한 마이그레이션을 기다릴 이유가 없어 P-1에 넣었다.

## 의도적으로 범위에서 뺀 것

- **관리자 화면**: 피드백을 읽을 UI를 만들지 않는다. 당분간 `wrangler d1 execute
  --remote`로 직접 쿼리하는 것으로 충분하다고 판단했다 — 과설계 방지. 피드백
  양이 늘면 그때 별도 논의.
- **추천/비추천의 자동 모더레이션**: 비추천이 쌓여도 자동으로 숨기지 않는다.
  몰아주기 비추천으로 콘텐츠가 자동 삭제되는 악용을 막기 위함. 정렬·발견용
  신호로만 쓴다.
- **자동 검증 규칙 확대**: 문항 작성 기준은 우선 문서 + 검수 화면 체크리스트로만
  적용한다. 의미적 품질(모호성 등)은 기계가 못 잡는 게 많아 규칙화 가능한 부분이
  드러나면 그때 validate.mjs에 편입하기로 함.
