# v2 로드맵 설계 (PLAN2.md 작성)

2026-08-13. 구현은 아직 없다. 프로젝트 재점검 + 새 요청사항 설계만 한 커밋.

## 왜

사용자가 콘텐츠 4종(타워 오르기 / 주제 선택 플레이 / 배틀 / 순위)과 추가 4종(전문가 난이도, 장르 세분화, 장르별 난이도 설정, 업적)을 제안했다. 바로 착수하지 말고 플랜부터 만들라는 지시였으므로, 현재 코드·데이터·스키마를 먼저 측정하고 그 위에 얹는 설계를 `PLAN2.md`로 남겼다.

## 재점검에서 드러난 것

1. **제안 ①타워와 ②주제 선택 플레이는 지금 같은 것이었다.** 현재 게임이 이미 "주제 고르고 12스테이지를 오르는" 구조라, 둘을 나누려면 한쪽을 새로 정의해야 했다.
2. **세부 장르는 스키마가 아니라 콘텐츠 문제다.** narrow 주제 15개와 `question_topics`(N:M)가 이미 있다. 막힌 건 문항 수뿐 — 단위 3 / 국기 6 / 시차 9 / 기록 9로 전부 하한 미달.
3. **난이도5는 랭킹 점수 체계를 건드린다.** 만점 1500은 "난이도 1~4 × 3스테이지 × 5문항 × 10점"에서 나온 값이라, 5단계를 넣으면 만점이 2250이 되고 기존 기록과 섞인다.

측정값: 총 264문항(MC 186 / NUMERIC 54 / TEXT 24), 공식 broad 3개 active + birds draft, narrow 15개 전부 미달, Cron Trigger 없음, Durable Objects 없음.

## 결정 (사용자 확인)

| # | 항목 | 결정 |
|---|---|---|
| ① | 타워 성격 | 전 주제 혼합 무한 타워 (주제 플레이는 현행 확장) |
| ② | "장르 당 난이도 설정" | 시작 난이도 선택 (오름차순 구조 유지) |
| ③ | 기존 랭킹 점수 | 시즌제 도입 — 시즌1 보존, 난이도5와 함께 시즌2 개시 |
| ④ | 세부 장르 하한 | 공식과 동일(20/난이도) 유지, 차는 순서대로 개방 |
| ⑤ | 배틀 | 보류 — 나머지 완성 후 실사용 반응 보고 재검토 |
| ⑥ | 난이도 명칭 | 기존 1~4(쉬움/보통/어려움/전문가) 유지 + 매니아(5) 추가, 기존 문항 재분류 없음 |

배틀을 보류한 근거: 실시간 대전은 Workers 구조상 Durable Objects가 필수인데 별도 프로비저닝이 필요하고, 동시 접속자가 적으면 매칭 자체가 성립하지 않는다.

## 로드맵

P0 난이도5+시즌제 스키마 → P1 문항 보충(116개) → P2 시작 난이도 선택 → P3 업적 → P4 타워 → P5 세부 장르(상시). 배틀 제외.

## 다음 작업자가 주의할 것

- P0에서 **테이블 재생성이 2건**이다: `questions`(difficulty CHECK 1→5 확장), `topic_best`(PK에 season_id 추가). 실사용자 데이터가 있으므로 `migrations/0002_add_text_input_and_images.sql`의 절차(자식 테이블 FK 먼저 제거 → 대상 재생성)와 이중 로컬 검증(기존 데이터 DB / 빈 DB 전체 순서 적용)을 반드시 반복한다.
- 시즌 전환 시 `users.global_score` 재계산은 되돌리기 어렵다. 시즌1 기록 아카이브 복사를 먼저 끝낸 뒤 전환한다.
- 난이도5 작업으로 `scripts/build-seed.mjs`를 다시 건드리게 된다 — 커뮤니티 문항을 지키는 `author_uid IS NULL` 범위 제한이 유지되는지 확인할 것.
- 일정을 지배하는 건 코드가 아니라 문항이다. 당장 116개, 세부 장르까지 보면 1,000개 단위다.
