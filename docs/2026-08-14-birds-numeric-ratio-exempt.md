# 새 맞추기 주제의 NUMERIC_INPUT 비율 경고 해소 + 작업 환경 능력 재확인

## 왜 이 작업을 했나

R2가 꺼져 있어 배포·이미지 관련 작업이 전부 막힌 상태에서, 막히지 않은 것부터 정리했다.

## ① `birds` 주제를 NUMERIC_INPUT 비율 검사에서 면제

`npm run validate`가 계속 이 경고를 냈다:

```
birds: NUMERIC_INPUT 비율 0% — 목표 20~25% 미달 (4.4절)
```

처음엔 숫자 답 문항(날개 길이, 수명 등)을 섞어 비율을 맞출 생각이었는데, `data/topics.json`의 주제 정의를 보고 생각을 바꿨다. 이 주제는 이렇게 정의돼 있다:

- `tagline`: "새 사진을 보고 학명을 맞혀보세요"
- `scope`: "사진으로 외형을 보고 종을 식별하는 것"
- **`outOfScope`: "사진 없이 울음소리·생태만으로 구별하는 문제"**

즉 숫자로 답하는 생태 문항은 **이 주제가 명시적으로 배제한 것**이다. 비율을 맞추려고 그런 문항을 넣으면 경고는 사라지지만 주제가 망가진다. 경고 쪽이 틀렸다.

**해법**: `topics.json`에 `numericRatioExempt` 필드(사유를 적는 문자열)를 두고, `validate.mjs`가 이 필드가 있으면 비율 검사를 건너뛰게 했다. 주제 id를 `validate.mjs`에 하드코딩하지 않은 이유는, 그러면 "왜 예외인지"가 코드에서 사라지기 때문이다. 사유를 데이터에 두면 주제 정의를 읽는 사람이 바로 납득한다.

검증:
- WARN 29건 → 28건 (birds 항목만 사라짐)
- **면제가 과하게 적용되지 않는지 회귀 확인**: `science.json`의 NUMERIC_INPUT을 임시로 전부 다른 타입으로 바꿔 돌렸더니 `science: NUMERIC_INPUT 비율 0%` 경고가 정상적으로 떴다. 원복함.
- `typecheck` / `build:seed` / `npm test`(162개) 전부 통과.

## ② 이 작업 환경에서 되는 것 / 안 되는 것을 실제로 확인

인수인계 문서에 "외부 접근 불가"라고 뭉뚱그려 적혀 있어서, 실제로 하나씩 눌러봤다. **갈린다:**

| | 결과 |
|---|---|
| `WebSearch` | ✅ **된다** (컨테이너 프록시를 안 거침) |
| `WebFetch` → `commons.wikimedia.org` | ❌ `EGRESS_BLOCKED` |
| `curl` → 프로덕션 URL | ❌ CONNECT 403 |
| GitHub API (MCP) | ✅ 된다 |
| `wrangler --local` | ✅ 된다 |
| `wrangler --remote` | ❌ **안 된다** — `CLOUDFLARE_API_TOKEN`이 이 컨테이너에 없다 |

두 가지가 중요하다:

1. **`WebSearch`가 된다** — 문서만 믿고 "외부 확인 불가"라며 조사를 포기하면 안 된다. 사실 확인은 여기서 할 수 있다. (다만 이미지 파일이 실제로 존재하는지는 `WebFetch`가 막혀 여전히 확인 불가라, "새 맞추기" 이미지 소싱은 그대로 막혀 있다.)
2. **`wrangler --remote`가 안 된다** — 앞선 커밋에서 인수인계 문서에 "프로덕션 D1 조회 가능"이라고 적었는데 **틀렸다.** 직접 실행해 확인하고 정정했다. 그래서 `npm run difficulty:review`(기본 `--remote`)도 이 환경에서는 못 돌린다.

인수인계 문서에 표로 정리해 넣었다.
