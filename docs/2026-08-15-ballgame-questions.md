# 구기(ballgame) 주제 활성화 — 54문항 추가

## 왜 이것부터

좁은 주제 16개가 전부 `draft`라 하나도 플레이할 수 없었다. 등록 구조와 자동 게이트는 설계대로 동작하고 **비어 있는 건 콘텐츠뿐**이었다.

전부 채우려면 1040 슬롯이라 한 번에 못 한다. **주제 하나를 끝까지 채워 실제로 `active`가 되는 것**을 첫 조각으로 잡았다 — 결손이 가장 적었고(54), 플레이 가능한 주제가 3개에서 4개로 늘어나는 눈에 보이는 결과가 나온다.

결과: `1:20 2:20 3:20 4:20` → **`active`**.

## ⚠ 앞선 추정이 틀렸다 — 좁은 태그는 배타적이다

인수인계에 "문항 하나가 좁은 태그를 2개까지 다니 실제 새 문항은 520개면 된다"고 적었는데 **틀렸다.** 기존 sports 80문항의 태그 분포를 세어 보면:

```
football 18 · ballgame 26 · olympics 17 · baseball 10 · record 9  =  80
```

조합 태그가 **하나도 없다.** 문항마다 `sports` + 좁은 태그 **정확히 1개**다. 그리고 그 태그들은 의미상 서로 배타적이다:

- `ballgame` = 축구·야구를 **뺀** 나머지 구기 (농구·배구·탁구·골프·테니스·럭비)
- `record` = 육상·복싱·사이클 등 **비구기** 기록 종목

PLAN 6.1은 좁은 태그 1~2개를 허용하지만, 실제 데이터는 배타적 분류로 굳어 있다. 억지로 2개를 달면 `validate`의 주제 쌍 겹침 규칙(PLAN 6.4 ⑤)에 걸리고, 무엇보다 플레이어가 두 주제를 골랐을 때 같은 문항을 다시 보게 된다.

**따라서 슬롯 1개 ≈ 문항 1개다.** 남은 실제 규모는 520개가 아니라 **약 986개**다(1040 − 이번 54). 인수인계를 정정했다.

유일하게 자연스러운 겹침은 `olympics` × 종목(예: "올림픽 축구 연령 제한")인데, 그것도 기존 데이터엔 없다.

## 무엇을 넣었나

| 난이도 | 개수 | 성격 |
|---|---|---|
| 1 | 14 | 드리블·서브·셔틀콕·스트라이크 등 용어와 기본 규칙 |
| 2 | 15 | 점프볼·듀스·버디/보기·리베로·로테이션 등 배운 사람은 아는 사실 |
| 3 | 12 | **규칙 개정 유형** (아래) |
| 4 | 13 | 코트·용구 규격, 세팍타크로·스쿼시·크리켓 등 덜 알려진 종목 |

종목은 농구·배구·탁구·배드민턴·테니스·골프·볼링·당구·핸드볼·럭비·아이스하키·스쿼시·세팍타크로·크리켓으로 흩었다. 축구·야구는 `ballgame`에 넣지 않는 기존 관례를 지켰다.

`NUMERIC_INPUT` 14개를 섞어 broad `sports`의 비율을 **24.6%**로 맞췄다(목표 20~25%, `scripts/lib.mjs`의 `NUMERIC_RATIO`). 좁은 태그에는 비율 목표가 없다 — `validate`가 broad에서만 본다.

### 난이도 3은 "규칙이 바뀐 것"으로만 채웠다

PLAN 6.5절과 `prompts/generate-questions.md`가 못 박고 있다 — **AI는 사람들이 무엇을 착각하는지 모른다.** 그래서 상상해서 만들지 않고, **옛 규칙으로 배운 세대가 실재하는 항목**만 골랐다:

| 문항 | 지금 | 예전 |
|---|---|---|
| 탁구공 지름 | 40mm | 38mm (2000년 개정) |
| 배구 마지막 세트 | 15점 | (일반 세트 25점과 다름) |
| FIBA 공격 리바운드 후 | 14초 | 24초 (2014년 개정) |
| FIBA 정규 시간 | 40분 | NBA 48분과 혼동 |
| 골프 깃대 꽂고 퍼팅 | 가능 | 벌타 (2019년 개정) |
| 배드민턴 서브 높이 | 1.15m 고정 | "허리 아래" |
| 배구 득점 | 랠리포인트제 | 서브권제(사이드아웃) |
| 그랜드슬램 마지막 세트 | 타이브레이크 | 두 게임 차까지 무제한 (2022년 통일) |
| FIBA 3점 라인 | 6.75m | 6.25m (2010년 개정) |
| 럭비 컨버전 | 2점 | 축구식 1점으로 오해 |

**12문항 전부에 `seedRef`를 달았다.** 이게 없으면 `validate`가 "진짜 많은 사람이 틀리게 아는 것인지 확인하라"고 WARN을 낸다 — 처음엔 이 규칙을 몰라 12개가 전부 걸렸다.

## validate가 잡아준 것

**`spo-432` 정답 유출** — "**라크로스**에서 공을 받고 던지는 그물 달린 채는?" 정답 "크로스". **문제 안에 정답이 그대로 들어 있었다**(라**크로스**). `scripts/fairness.mjs`의 `choiceAnswerLeaked`가 잡았다. 문항을 크리켓 볼러 문제로 통째로 교체했다.

`2026-08-14-question-fairness.md`에서 만든 규칙이 실제로 새 문항을 막아 세운 첫 사례다.

## 검증

- `npm run validate` — **내 문항에서 나온 WARN 0건** (남은 WARN은 전부 기존 sci-/spo- 최상급 표현)
- `npm run build:seed` — 구기 `1:20 2:20 3:20 4:20` → **`active`**
- `npm test` 211개 통과 · `npm run typecheck` · `npm run build` 통과
- sports broad: 80 → 134문항, NUMERIC 24.6%
