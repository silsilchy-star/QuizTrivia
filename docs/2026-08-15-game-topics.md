# 게임 주제 — 포켓몬스터·마인크래프트·리그오브레전드 240문항

## 요청

*"주제 게임 위주로 3개 정도 늘려줄래 / 포켓몬스터, 마인크래프트, 리그오브레전드 / 게임 캐릭터의
이미지를 보고 서술형으로 입력해서 맞추는 방식으로 문제 늘려줘"*

형식(이미지 + 단답형)은 이미 있던 조합이다. "새 맞추기"가 쓰던 바로 그것이고, 직전 작업에서
단답형에 "또 맞는 답"(`answerAliases`)까지 붙여둔 상태였다 — 이 주제들이 그 기능을 제대로
쓰는 첫 사례다. 포켓몬 이름을 한글로 쓰든 영문으로 쓰든 맞다고 처리된다.

## 결과

| 주제 | 문항 | 이미지 문항 | 상태 |
|---|---|---|---|
| 게임 (넓은 주제) | 240 | 230 | ✅ active |
| ├ 포켓몬스터 | 80 | 80 | ✅ active |

플레이 가능한 주제 8개 → **12개**, 공식 문항 560 → **800**개.

## ⚠ 저작권

세 게임의 캐릭터·텍스처 이미지는 각각 닌텐도/게임프리크, 모장/마이크로소프트, 라이엇의
저작물이다. 팬 프로젝트가 널리 쓰는 경로(PokeAPI, Data Dragon, mcmeta)에서 가져왔지만
공개 서비스인 이상 권리자 판단에 따라 문제가 될 수 있다. 서비스 주인이 알고 진행한 사항이다.

## 이름과 수치를 기억으로 쓰지 않았다

이게 이 작업의 핵심 결정이다. sports 난이도 3의 100문항은 지금도 사람 검수를 기다리고 있다 —
연도와 수치를 확인 없이 적었기 때문이다. 같은 부채를 또 만들지 않으려고, **각 게임의 공식
데이터를 받아 거기서 그대로 뽑는 생성기**(`scripts/gamedata/`)로 만들었다.

| 게임 | 이름·설명 출처 | 이미지 |
|---|---|---|
| 포켓몬 | PokeAPI `api-data` — 한국어 `names`·`genera`(도감 분류)·`flavor_text`(도감 설명) | PokeAPI sprites 공식 아트워크 |
| 마인크래프트 | mcmeta `lang/ko_kr.json`(공식 한글 번역), `item_components`(최대 스택 수) | mcmeta 자바 에디션 기본 텍스처 |
| 롤 | Data Dragon `ko_KR/champion.json` — 공식 한글 챔피언명과 별명 | Data Dragon 챔피언 초상 |

해설도 마찬가지다. "피카츄(Pikachu)는 1세대 쥐포켓몬으로 전국도감 25번입니다. 도감 설명: …"에서
**쥐포켓몬도 도감 설명도 공식 데이터에서 온 문자열**이다.

데이터에 없어서 사람이 정한 것은 두 가지뿐이고, 생성기 안에 표로 분리해 뒀다 — **난이도 배치**와
**난이도 3의 "왜 헷갈리는지"**.

## 프록시가 막아서 GitHub 미러를 썼다

이 작업 환경은 `ddragon.leagueoflegends.com`과 `minecraft.wiki`, `pokeapi.co`를 전부 막는다
(curl도 WebFetch도 동일). 뚫려 있는 건 `raw.githubusercontent.com`뿐이라 세 게임 모두 GitHub
경로로 받았다. **이게 오히려 다행이었다** — 이미지 URL을 이 환경에서 직접 검증할 수 있었기
때문이다.

**230개 이미지 URL을 전부 HTTP 200으로 확인했다.** "새 맞추기"가 죽은 이유가 검증하지 못한
외부 이미지였다(인수인계 6번). 같은 실수를 반복하지 않으려고 넣기 전에 전수 확인했고, 확인
방법은 `scripts/gamedata/README.md`에 적어뒀다.

## 구조 — 왜 broad "게임" 밑에 좁은 주제 3개인가

처음엔 세 게임을 각각 넓은 주제로 넣었는데 **롤에서 규칙 충돌이 났다.**

넓은 주제는 NUMERIC_INPUT 비율 20~25%를 맞춰야 한다(`NUMERIC_RATIO`). 그런데 롤에서 쓸 수 있는
수치는 대부분 **패치마다 바뀐다** — 챔피언 체력·쿨다운·아이템 가격을 넣으면 패치 한 번에 틀린
문항이 되고, 틀린 걸 알아채는 사람도 없다. 패치와 무관한 고정 구조(한 팀 5명, 최대 18레벨,
궁극기 6레벨, 라인 3개…)만 추리면 열 개 남짓이라 20%를 못 채운다.

억지로 채우는 대신 **스포츠와 같은 구조**로 바꿨다 — 넓은 주제 `게임` 아래 좁은 주제
포켓몬·마인크래프트·롤. 비율 규칙은 넓은 주제에만 걸리므로, 포켓몬 20 + 마인크래프트 20 +
롤 10 = 50/240 = **20.8%**로 자연스럽게 들어맞는다. 덤으로 세 게임이 섞여 나오는 `게임`
주제가 하나 더 생겼다.

## 유형 구성

요청대로 **이미지 보고 이름 입력**이 중심이다.

| 주제 | 단답형 | 숫자입력 |
|---|---|---|
| 포켓몬스터 | 60 (이미지 → 한글 이름) | 20 (이미지 → 전국도감 번호) |
| 마인크래프트 | 60 (이미지 → 블록·아이템 이름) | 20 (이미지 → 한 칸에 겹치는 개수) |
| 리그오브레전드 | 70 (이미지 → 챔피언 이름) | 10 (협곡의 고정 구조) |

별칭은 전 문항에 붙였다 — 포켓몬·챔피언은 영문명, 마인크래프트는 영문 id. `피카츄`도
`Pikachu`도 `pikachu`도 정답이다.

### 마인크래프트는 "캐릭터"가 아니라 블록·아이템이다

요청은 캐릭터였지만 마인크래프트의 몹은 GitHub에서 받을 수 있는 형태가 **UV 텍스처 아틀라스**
(펼쳐진 가죽) 뿐이라 그림 문제로 쓰기 어렵다. 대신 블록·아이템 텍스처를 썼다 — 플레이어가
인벤토리에서 실제로 보는 그림 그대로라 오히려 알아보기 쉽다.

### 난이도 3을 어떻게 잡았나

이 프로젝트의 난이도 3은 "많은 사람이 틀리게 아는 것"이다. 그림 문제에서는 **비슷하게 생겼거나
이름을 착각하는 대상**이 정확히 여기 해당한다.

- 포켓몬: 라티아스/라티오스, 디아루가/펄기아, 이브이 진화형 셋, 탕구리/텅구리
- 마인크래프트: 가공하지 않은 철/금/구리(모양이 같고 색만 다름), 심층암/응회암/방해석
- 롤: 자야/라칸, 스웨인/사일러스, 나서스/레넥톤, 직스/하이머딩거, 공허 챔피언들

**⚠ 마인크래프트 문항에는 버전 번호를 하나도 적지 않았다.** "1.17에서 바뀌었다" 같은 문장은
확인하지 못한 수치라 적는 순간 사실 검수 부채가 된다. 대신 "생김새가 비슷해 헷갈린다"처럼
그림에서 확인 가능한 이유만 적었다.

`seedRef`는 실제로 답을 뽑아낸 데이터 URL을 그대로 달았다. 열어보지 못한 위키 링크보다
**기계로 대조할 수 있는 출처**가 낫다.

## 남은 것

- **실제 화면 확인은 사람이 해야 한다.** 이 환경은 프록시가 `workers.dev`를 막아 배포된 화면을
  열 수 없다. 이미지가 뜨는지, 한글 이름을 입력했을 때 정답 처리되는지 확인이 필요하다.
- 롤 챔피언은 계속 추가된다. 새 챔피언을 넣고 싶으면 `fetch.sh`로 최신 데이터를 받아
  `gen_lol.py`의 난이도 표에 id만 추가하면 된다.
