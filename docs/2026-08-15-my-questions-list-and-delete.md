# 창작마당: 내 문항 목록 + 개별 삭제

## 왜 필요했나

창작마당 주제 화면에는 두 개의 버튼밖에 없었다 — **"+ 문제 추가"**와 **"이 주제 삭제"**.

즉 창작자는 자기가 만든 문항을 **볼 수도 없고, 하나만 지울 수도 없었다.** 오타 하나를 발견하면 선택지가 두 개뿐이다:

1. 틀린 문항을 그대로 두고 산다
2. 주제를 통째로 지우고 처음부터 다시 만든다

만드는 기능만 있고 고치는 길이 없는 구조다. 그리고 바로 앞 커밋(`ebebeb5`)에서 영상 첨부가 들어가면서 이게 더 나빠졌다 — **영상은 삭제·비공개될 수 있어서 링크가 죽는 일이 이미지보다 잦다.** 죽은 영상 하나 때문에 주제를 날려야 한다면 영상을 붙일 이유가 없어진다.

## ⚠ 이 목록에는 정답이 들어있다

문항 목록은 `answer`와 `explanation`을 담는다. 이건 **작성자 본인에게만** 내려가야 한다 — 남이 볼 수 있으면 그 창작 주제는 정답표를 펴놓고 푸는 것과 같아진다.

플레이 중 내려가는 `ServedQuestion`에 정답이 없는 것(서버 채점, PLAN 7.5절 A안)과 **같은 종류의 경계선**이다. 다만 여기서는 "출제 전이냐 후냐"가 아니라 "내 주제냐 남의 주제냐"로 가른다.

```
GET /api/community/topics/:id/questions
  → 주제 없음        404
  → 내 주제 아님      403   ← 이 줄이 무너지면 정답 유출
  → 내 주제          200 + 정답·해설 포함
```

테스트가 이 경계를 직접 지킨다(`남은 그 목록을 볼 수 없다 — 정답이 실려 있기 때문`). 응답 본문에 정답 문자열이 없는 것까지 확인한다.

## 삭제에서 조심한 것

### 주제 소유 확인만으로는 부족하다

내 주제를 갖고 있다고 해서 아무 문항 id나 지울 수 있으면 안 된다. **그 문항이 정말 이 주제에 속하는지**를 따로 확인한다:

```sql
SELECT 1 FROM question_topics WHERE topic_id = ? AND question_id = ?
```

없으면 404. 이게 없으면 "내 주제 하나만 만들면 남의 문항을 마음대로 지울 수 있는" 경로가 된다. 테스트로 못 박아 뒀다(`내 주제에 속하지 않은 문항 id로는 지울 수 없다`).

### 삭제 순서와 범위

```sql
1. DELETE FROM question_stats WHERE question_id = ?          -- FK가 없어 고아가 남는다
2. DELETE FROM question_topics WHERE topic_id = ? AND question_id = ?
3. DELETE FROM questions
    WHERE id = ? AND author_uid = ?                          -- 공식 문항 보호
      AND NOT EXISTS (SELECT 1 FROM question_topics WHERE question_id = ?)
```

3번의 `NOT EXISTS`는 이 문항이 다른 주제에도 걸려 있다면 남겨두기 위한 것이다. 지금 커뮤니티 문항은 주제 하나에만 붙지만, 조건이 안전하게 쓰여 있어야 나중에 이 코드를 본뜨는 사람이 다치지 않는다 (`migrations/0002`에서 같은 판단을 했다).

`question_stats`를 먼저 지우는 건 `migrations/0002`와 같은 이유다 — 그 테이블에는 `questions(id)` FK가 없어서 그냥 두면 참조 대상이 사라진 행이 남는다.

### 게이트 재계산은 추가·삭제가 같은 함수를 쓴다

문항이 줄면 하한 아래로 내려갈 수 있고, 그러면 `active`였던 주제는 **`draft`로 되돌아가야 한다.** 안 그러면 "플레이할 수 있다고 표시되는데 실제로는 문항이 모자라는" 주제가 생긴다.

추가 경로에 있던 재계산 로직을 `recountTopic()`으로 빼서 추가·삭제가 같은 함수를 부르게 했다. 한쪽만 고쳐서 규칙이 어긋나는 걸 막는 게 목적이다.

## 수정 기능은 넣지 않았다

지우고 다시 넣으면 되기 때문이다. 수정은 재검증 · 중복 재확인 · 게이트 재계산 · 기존 통계 처리를 전부 다시 밟아야 해서 표면이 훨씬 넓고, 삭제만으로 모든 나쁜 상태에서 빠져나올 수 있다.

## UI

주제 상세 화면 아래에 문항 목록이 붙는다. **붙인 이미지·영상을 함께 보여주는 게 핵심이다** — 잘못 붙인 링크나 죽은 영상은 목록에서 눈으로 봐야 찾을 수 있다. 삭제는 주제 삭제와 같이 확인 단계를 거친다.

목록은 문항 수가 바뀔 때(추가·삭제) 다시 읽는다.
